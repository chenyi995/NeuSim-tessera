# Tessera in NeuSim

This document describes the earlier **custom analytical backend**, which bypasses
NeuSim's native memory, VU and power path. Its results must not be described as
native NeuSim cross-validation. For the same-workload comparison that preserves
native accounting, see [tessera_native.md](tessera_native.md).

The optional `array_backend="tessera"` routes NeuSim's public
`fill_operators_execution_info` entry to an analytical array and tensor-residency
model. The original backend remains the default. The Tessera backend accepts
native einsum and fused-attention operators, and explicit dependency graphs via
`Operator.tessera_spec`. It fills native timing/energy statistics and retains
detailed counters in `OperatorStatistics.tessera_details`.

This implementation estimates timing and energy. It does not execute neural
network values, replace RTL verification, or establish timing closure.

## Resources and provenance

`configs/chips/tessera_revision.json` is generated by `prepare_tessera.py` from
the FissionSA revision configuration, inherited energy constants, saved workload
metadata, and the paper's idle-array timeline. Its `parameters`, `sources`, and
`assumptions` fields are the authoritative numerical specification. Reference
files are read only. Every run saves its configuration, hashes, source snapshots,
command, summary, read-back checks and completion status in a new directory.

All comparisons use the same PE count, clock, SRAM capacity, operand precision,
vector throughput and HBM assumptions. SRAM ports are unconstrained, matching the
revision reference. Resources are equal by PE count, not by synthesized area.
The background term is a linear PE-count projection of observed idle-array power;
controller, SRAM and DRAM static power are not calibrated. HBM energy uses
transferred read/write bytes and the inherited per-byte coefficients, not DRAM
commands, refresh, or row-buffer state. Vector energy borrows the array arithmetic
coefficient as a coarse estimate.

The user authorized at most 16 CPU cores and 100 GB RAM. The runner sets CPU
affinity and address-space limits; numerical libraries use one thread. Trace
workers share the affinity and divide the address-space allowance across parent
and workers. No GPU is needed.

## Array variants and timing

| Variant | Meaning |
|---|---|
| `tessera` | Uniform dyadic rectangular physical slots, with registered seams and no skew |
| `square` | Square physical allocation, with logical tiles independently selected for EDP |
| `square_fixed` | The Tessera-selected logical tiles, padded to square physical allocation |
| `independent` | Fixed grain-sized arrays, no inter-array PE links, skew-free, common SRAM and vector reduction unit |
| `skew` | The same logical tiles as Tessera with traditional skew/de-skew timing restored |
| `ws` | A monolithic weight-stationary array with traditional skew/de-skew |

The mapping search permits powers of two between `grain` and `side`. Rectangles
can rotate; the short dimension is the local pipeline depth. Logical tails keep
the same slot as full tiles. This restricted mapper does not implement arbitrary
rectangles, heterogeneous concurrent slots, or cross-GEMM packing. All variants
execute useful arithmetic only; physical padding does not create MACs or tensor
traffic. Independent arrays can combine K partials through SRAM and vector adds.

`bank_cycles` is the closed form of the two-bank recurrence in
`FissionSA/fissionsa/revision_arrays.py::_bank_cycles`:

```
F[0] = 0; I[0] = H
F[f] = max(F[f-1] + H, I[f-2] + M + release)
I[f] = max(F[f] + H, I[f-1] + M)
release = 0 without skew, H-1 with skew
drain = H-1 without skew, 2H-2 with skew
```

Rectangular chains add `W-H`, an ingress transpose fill, and registered strip
seams. `gemmini/partition/TIMING_AUDIT.md` supplies array-boundary timing anchors.
The staged full-adapter initiation interval is not substituted for array II.
The model assumes subsequent transpose fills overlap through buffering. It has
not been calibrated against complete RTL executions for all logical mappings.

GEMM mapping minimizes modeled energy times time, including transfers, SRAM
partial-sum reads/writes, vector reductions and background. Fixed ablations use
the Tessera-selected mapping. Square-fixed results measure the padding penalty
at that mapping; large penalties cannot be attributed to an optimized square-only
design, which must use the separate `square` result.

## Memory and energy accounting

The GEMM memory planner chunks M and N so that input rows, live FP32 accumulators,
retained weights where feasible, and transfer staging fit SRAM. It retains weights
or streams/reloads them according to capacity. Whole tensors use a conservative
LRU at operator boundaries. Workspace is reserved in addition to surviving whole
tensors, so overlapping resident inputs may spill unnecessarily. This trades
optimistic reuse for a reproducible capacity bound.

Array operand reads, FP32 partial writes and cross-K reductions are counted
separately. The first load and last store bound within-operator HBM/compute overlap.
Operators serialize. A common helper applies the same overlap calculation to
mapping selection and final timing. Array energy is useful MACs times two arithmetic
operations times `array_pj_per_op`. Reduction work belongs to the vector component.
Background power is multiplied by each serial operator's duration exactly once.

Fused attention performs QK, softmax and PV within SRAM-sized query/KV blocks.
Heads sharing KV are folded into the stream dimension, with separate requests
retaining separate caches. Scores do not spill to HBM; repeated KV loads across
query blocks do. Attention uses full logical rectangles, including causal-masked
positions, matching the source MNK traces. It does not model triangular skipping.
Scalar exp/div/tanh costs follow NeuSim's scalar-operation approximation. Running
softmax/output state traffic is approximate. Small GEMMs use the selected array
instead of the original small-matmul vector fallback.

Skew-register and link switching energy are not independently calibrated. The
paired skew experiment therefore preserves all dynamic components and changes
only timing-dependent array background. It supports a timing ablation, not a
claim of measured skew-register energy savings.

## Workloads and the E2E boundary

LLM graphs use the saved model dimensions and per-request query/KV lengths.
They include embedding, normalization, QKV, bias where specified, RoPE, KV append,
fused attention, output projection, residuals, gated/ungated FFN, tensor-parallel
projection allreduces, final normalization, LM head and argmax. Phi uses its parallel
residual topology, conservatively serialized on shared resources. The graph
charges the KV append to HBM and reads those bytes again with the cache. Sin/cos
table traffic and final TP token-choice communication are omitted. Every replay
batch produces one logit row per request, including incomplete prefill chunks.

The trace suite replays every saved batch from all source files. It sums accelerator
model-step service time, not arrival gaps, queueing, TTFT, inter-token latency,
host scheduling or CPU sampling time. The batching policy is fixed across variants.
Model-step accounting is the E2E boundary in these results. Energy columns are per
chip; `system_energy_J` multiplies by TP ranks once. Homogeneous layers may be
represented once with a repeat count; tests compare this with explicitly expanded
graphs, including real prefill shapes and Phi bias operations.

The DNN supplement reads the Planaria network definitions used as reference
workloads. It preserves branches, concatenation/addition, pooling and the reference
scalar-activation count. Implicit im2col supplies array operands without writing
an expanded matrix to DRAM. Depthwise layers are channelwise GEMMs, not dense
convolutions. These are reference layer graphs, not complete framework exports;
GNMT entries represent the provided encoder/decoder layer graphs. The separate
revision operator suite preserves occurrence weights and reports standalone
kernel results. It must not be labeled whole-model E2E.

## Reproduction and validation

Use the project-local `.venv`. The experimental runner needs the normal NeuSim
frontend dependencies, including Pydantic, and Matplotlib for exported figures;
it does not use Ray. From the NeuSim root:

```bash
.venv/bin/python -B -m unittest \
  neusim.npusim.backend.tests.test_tessera \
  neusim.configs.tests.test_chip_config \
  neusim.npusim.frontend.tests.test_operator \
  neusim.npusim.backend.tests.test_power_model
.venv/bin/python -B -m neusim.run_scripts.run_tessera --suite pilot --cpus 16 --memory-gb 100
.venv/bin/python -B -m neusim.run_scripts.run_tessera --suite traces --cpus 16 --memory-gb 100
.venv/bin/python -B -m neusim.run_scripts.run_tessera --suite dnn --cpus 16 --memory-gb 100
.venv/bin/python -B -m neusim.run_scripts.run_tessera --suite operators --cpus 16 --memory-gb 100
.venv/bin/python -B -m neusim.run_scripts.run_tessera --suite sensitivity --cpus 16 --memory-gb 100
```

Run authorization and the stated combined resource budget still apply; these
commands are reproduction instructions, not instructions to launch duplicate runs.
Existing result directories cannot be overwritten. The sensitivity suite uses the
reference bandwidth scenarios and the approved relative HBM energy factors.

Backend edits require the independent bank event schedule, RTL anchor comparison,
capacity/MAC conservation and fixed-ablation checks in `test_tessera`. The event
test covers each dimension, stream length, fold count and skew flag enumerated in
that test with exact integer equality. Frontend and workload edits require native
operator integration, residency, compact/expanded layer and depthwise checks in
the same module, plus the native configuration/operator/power regressions above.
Floating energy/time comparisons use relative tolerance for summation order;
integer bytes, MACs, source rows and timing anchors require exact equality.

Each run checks CSV readback and component energy sums. The independent
`verify_tessera` command takes `--pilot`, `--traces`, `--dnn`, `--operators` and
`--sensitivity` result directories. It regroups source traces through a separate
reader, checks all saved batch MACs including LM head, checks batch coverage and
totals, and verifies paired dynamic-energy invariants. It writes a new review
directory with full-precision facts, source hashes and a report. The report and
plotting scripts derive every numerical table/figure from saved CSVs.
